# Work Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the cluttered Punch / Customer Visit / Site Work buttons with one clean "Work ON → mode → purpose/task → run / pause / stop → Work OFF" block, with admin live view and reports.

**Architecture:** Field Work is the existing Customer Meeting flow (`Meetings` sheet, `Customers` leads) extended with purposes, pause/resume and outcome. Office and WFH tasks go into a new `WorkLogs` sheet. Admin live view and reports read both through one normalised row shape. The employee home screen is rebuilt in the Tasks glass style under a new `.wmx` scope.

**Tech Stack:** Single-file `index.html` (vanilla JS, GitHub Pages); backend `src/backend.gs` run by the Firebase engine (`GasBridge`, Firestore); tests `node --test` in the functions dir; browser tests with the Playwright harness in `scratchpad/h_notif/`.

**Spec:** `docs/superpowers/specs/2026-10-16-work-mode-design.md`

## Global Constraints
- Modes: `field` = "Field Work", `office` = "Office Work", `wfh` = "Work From Home".
- Field purposes, in order: Sales Meeting, Site Supervision, Complaint, Payment Collection, Installation, Brand Building, Material Delivery, Other (text required).
- Office/WFH tasks, in order: Client Calling, Accounts Setting, Accounts Settling, Task Stack Settling, Training, Client Code Creation, Client Presentation Making, Demo to Office Client, Other (text required). Client name + phone required for Client Calling and Demo to Office Client.
- Only one item (meeting or task) may be running or paused per employee at a time.
- Stop needs feedback: Sales Meeting keeps the existing result list (`MEETING_RESULTS`); every other item needs a non-empty one-line outcome/remarks.
- The home block shows **Total working hours** (Work ON → now, or → Work OFF once ended) and **Productive working hours** (sum of the Active minutes of all meetings and tasks that day; pauses, travel and unlogged time are not productive). The old "in office so far" / "total in office" captions are removed from the employee screen.
- Employee labels are **Work ON / Work OFF** (data stays `punchIn` / `punchOut`; admin screens, reports and CSV keep saying Punch In / Punch Out). Mode cards: English + a Hindi hint ("बाहर का काम", "ऑफिस", "घर से").
- Day Work ON keeps photo + GPS exactly as Punch In does today; per-task GPS is not required for Office/WFH.
- Glass theme, line icons, 44 px touch targets, text wraps inside its box, no horizontal scroll at 320 px.
- Don't change existing responses' fields (add only). Old Meetings/Visits rows without new fields must still work.
- Visibility uses `scopeSet()` / `inSet()`: Super Admin all, Dept Admin department, Supervisor own staff.
- A push to `main` or a production deploy needs the user's "haan" in chat at each phase gate. Final step of a release: `python3 tools/release.py "what changed"`, commit, push.

## Review Focus
1. Stop pressed while paused → the open pause is closed at that moment; active time excludes it.
2. Work OFF while an item is running or paused → refused with a message naming the item.
3. Same `workStart` / `workStop` sent twice (offline retry, double tap) → one row, same result.
4. An item left running past midnight or at Work OFF day end → shown "Open since yesterday", closed by the next Work OFF with a flag, never counted as 20+ hours of active time (cap at the punch-out time).
5. Same employee on two phones starting a second item → refused "already running".
